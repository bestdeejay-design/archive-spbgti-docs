# Анализ требований к архиву СПбГТИ

**Дата:** 03.09.2026
**Источник:** «требования к архиву.txt» (внешний документ)
**База для сравнения:** SPEC.md v2.0 (03.07.2026), текущая реализация v1.0.0

---

## 1. Ключевые принципы из требований

| Принцип | Описание |
|---------|----------|
| **Архив как сервис** | Не хранилище, а удобный продукт для пользователя |
| **Ориентация на пользователя** | Консистентная система, напоминающая учебник, с поддержкой оригиналов |
| **Стандартизированная каталогизация** | Глубокое индексирование: имена, темы, география (модель Library of Congress / WorldCat) |
| **Сообщество выпускников** | Персональный поиск: год выпуска, факультет, имя; сохранение воспоминаний |
| **Навигация по периодам** | Тематические коллекции и хроники, группировка по эпохам/событиям |

## 2. Многомерная классификация: 5 осей

### 2.1. Требуемые оси

| № | Ось | Описание | Текущий статус в SPEC |
|---|-----|----------|----------------------|
| 1 | **Хронологическая** | Годы и десятилетия (декады: 1920-е, 1930-е...) | ✅ Частично реализовано: поле `decade` + фильтр по десятилетию |
| 2 | **Структурная** | Факультеты и кафедры (историческая структура института) | ❌ Отсутствует |
| 3 | **Персональная** | «Карточка студента/преподавателя» с привязкой всех материалов | ❌ Отсутствует (поле `people` — текстовое, без связей) |
| 4 | **Событийная** | Группировка по событиям/мероприятиям | ❌ Частично: категория `event`, но без карточек событий |
| 5 | **Тематическая** | Глобальные темы (лаборатории, здания, студжизнь, преподаватели) | ❌ Отсутствует |

### 2.2. GAP-анализ по осям

#### Ось 1: Хронологическая — 🟡 Частично

**Есть:**
- Поле `decade` (string) в коллекции `Archive`
- Фильтр по десятилетию в галерее

**Нет:**
- Автоматическое заполнение `decade` из `date_taken` (сейчас вручную)
- Группировка по конкретным годам внутри десятилетия
- Хронологическая шкала (таймлайн) для навигации

**Рекомендация:** Добавить вычисляемое поле `decade` на основе `date_taken` или триггер при сохранении. Реализовать навигацию через хронологическую шкалу.

---

#### Ось 2: Структурная — 🔴 Отсутствует

**Есть:**
- Категория `teachers` и `students` (текстовые поля)

**Нет:**
- Справочник факультетов/кафедр (историческая структура института)
- Связь записей с факультетами
- Иерархия: институт → факультет → кафедра → группа

**Рекомендация:** Создать коллекцию `Faculties` (id, name, abbreviation, years_active, description). Добавить поле `faculty` (relation) в `Archive`. Создать коллекцию `Departments` (кафедры) с привязкой к факультетам.

---

#### Ось 3: Персональная — 🔴 Отсутствует

**Есть:**
- Текстовое поле `people` в `Archive` (строка)

**Нет:**
- Отдельная коллекция `Persons` (карточки людей)
- Связь «многие-ко-многим»: запись ↔ персоны
- Профиль персоны: имя, годы жизни, роль (студент/преподаватель), фото, биография
- Автоматическая привязка всех упоминаний к карточке

**Рекомендация:** Это ключевое требование. Создать:
- Коллекцию `Persons` (id, full_name, birth_date, death_date, role, bio, photo, faculty_id)
- Связующую таблицу `Archive_Persons` (many-to-many)
- Интерфейс «Карточка персоны» с агрегацией всех связанных материалов

---

#### Ось 4: Событийная — 🟡 Частично

**Есть:**
- Категория `event` в `Archive`
- Поле `date_taken`

**Нет:**
- Отдельная коллекция `Events` (идентификатор события)
- Карточка события: обложка, описание, дата, галерея
- Связь записей с событиями

**Рекомендация:** Создать коллекцию `Events` (id, title, date, description, cover_image, event_type). Добавить поле `event` (relation) в `Archive`. Реализовать страницу события с автоматической галереей.

---

#### Ось 5: Тематическая — 🔴 Отсутствует

**Есть:**
- Категории: event, students, teachers, buildings, documents, other

**Нет:**
- Система тегов (tags) для тематической навигации
- Тематические подборки/коллекции
- Связь записей с темами

**Рекомендация:** Создать коллекцию `Tags` (id, name, group). Добавить связь many-to-many `Archive ↔ Tags`. Реализовать тематические коллекции (например, «Научные лаборатории», «История зданий», «Студенческая жизнь»).

## 3. Уровни доступа: 4 модели

### 3.1. Требуемые уровни

| Уровень | Роль | Возможности | Текущий статус |
|---------|------|-------------|---------------|
| **Уровень 1** | Гости / Простые пользователи | Доступ к контенту без регистрации | ✅ Реализовано (публичная галерея) |
| **Уровень 2** | Зарегистрированные | Избранное, персональные подборки, предложения контента | ❌ Отсутствует |
| **Уровень 3** | Продвинутые / Сообщество | Модерация контента по курсу (подтверждение личностей на фото) | ❌ Отсутствует |
| **Уровень 4** | Администраторы | Полный контроль | ✅ Реализовано (Administrator) |

### 3.2. Текущие роли Directus

| Роль | admin_access | app_access | Ограничения |
|------|-------------|-----------|-------------|
| Administrator | true | true | Полный доступ |
| Editor | true | true | Скрыты Users/Permissions через CSS |
| Uploader | false | false | Только загрузка файлов |
| API Gallery | — | — | Статический токен, только чтение |

### 3.3. GAP-анализ

**Уровень 2 (Зарегистрированные):**
- ❌ Нет системы регистрации пользователей (саморегистрация)
- ❌ Нет функции «Избранное»
- ❌ Нет персональных подборок
- ❌ Нет возможности «Предложить контент» (форум/обсуждение)

**Уровень 3 (Продвинутые / Сообщество):**
- ❌ Нет роли «Модератор курса»
- ❌ Нет возможности подтверждать личности на фото
- ❌ Нет системы «Подтверждений» (moderation queue)

**Рекомендация:** Directus поддерживает кастомные роли и поля. Можно:
1. Включить саморегистрацию (`REGISTRATION_ENABLED: true`) для Уровня 2
2. Создать роль `Alumni` с ограниченными правами (комментарии, избранное)
3. Создать роль `CourseModerator` с правами модерации определённых записей
4. Добавить систему комментариев/обсуждений через отдельную коллекцию

## 4. Структура контента

### 4.1. Правило «Папок»

**Требование:** Не использовать строгую иерархию «папок». Вместо этого — теги и связи. Один файл должен быть виден в нескольких разделах одновременно.

**Текущее состояние:** Прямая иерархия `Archive → file`. Нет связей many-to-many.

**Рекомендация:** Внедрить:
- Связи many-to-many: `Archive ↔ Persons`, `Archive ↔ Events`, `Archive ↔ Tags`
- Виртуальные «подборки» на основе связей (а не физические папки)
- Одна запись автоматически попадает в: «Выпуск 1985», «Факультет Энергетический», «Событие: Выпускной», «Персона: Иван Иванович»

---

### 4.2. Публикация по периодам

**Требование:** Группировка по «эпохам» с лимитами по годам (например, «Советская эпоха (1960-1990)», «Современность (2000-2025)»).

**Текущее состояние:** Фильтр по десятилетиям (1920-е, 1930-е...), но без понятия «эпоха».

**Рекомендация:** Создать коллекцию `Eras` (id, name, start_year, end_year, description). Привязать десятилетия к эпохам. Реализовать навигацию по эпохам в галерее.

---

### 4.3. «Карточка события»

**Требование:** Для каждого мероприятия — страница с обложкой, описанием, датой и автоматической галереей фото/Видео с тегом.

**Текущее состояние:** Отсутствует.

**Рекомендация:** Реализовать коллекцию `Events` (см. Ось 4) + отдельную страницу `/event/:id` с автоматической подгрузкой связанных записей.

---

## 5. Интеллектуальный поиск и фильтры

### 5.1. Базовые фильтры

**Требование:** Годы (выпадающий список) + Факультет + Тип контента (Фото/Документ/Видео).

**Текущее состояние:**
- ✅ Фильтр по категории (7 шт)
- ✅ Фильтр по десятилетию
- ❌ Фильтр по году (конкретному)
- ❌ Фильтр по факультету
- ❌ Фильтр по типу контента (фото/документ/видео)

**Рекомендация:**
1. Добавить фильтр по году (на основе `date_taken`)
2. Добавить фильтр по факультету (после создания коллекции `Faculties`)
3. Добавить фильтр по типу файла (на основе `file.type`)

---

### 5.2. Поиск по лицу (Face Recognition)

**Статус:** Перспективное развитие.

**Рекомендация:** Пока не требуется. В будущем — интеграция с ML-сервисом (например, AWS Rekognition, Google Vision, или open-source solutions). Технически реализуемо через:
- Отдельный Docker-контейнер с ML-моделью
- API для поиска по векторному представлению лица
- Привязка результатов к коллекции `Persons`

---

### 5.3. Поиск по тексту (OCR)

**Статус:** Перспективное развитие.

**Рекомендация:** Пока не требуется. В будущем — интеграция с OCR-движком (Tesseract, Google Vision OCR). Технически:
- Отдельный Docker-контейнер с Tesseract
- Обработка загруженных документов (PDF, изображения)
- Извлечение текста → сохранение в `ocr_text` поле `Archive`
- Полнотекстовый поиск по `ocr_text`

## 6. Интерактив для выпускников

### 6.1. Личный кабинет выпускника

**Требование:** Раздел «Моя история» — все записи, связанные с именем выпускника, + возможность добавить воспоминания.

**Текущее состояние:** ❌ Отсутствует.

**Рекомендация:** Реализовать через:
1. Авторизацию пользователя с привязкой к `Persons` (поле `user_id`)
2. Запрос: `GET /items/Archive?filter[persons][_in]=<my_person_id>`
3. Страницу `/my-history` с агрегацией всех связанных записей
4. Форму добавления воспоминаний (текст + фото)

---

### 6.2. Альбомы выпусков

**Требование:** Виртуальные альбомы для каждого выпускного года, которые можно «листать» и дополнять.

**Текущее состояние:** ❌ Отсутствует.

**Рекомендация:** Реализовать через:
1. Коллекцию `GraduationAlbums` (id, year, faculty, description, cover)
2. Связь с `Archive` через `event` (событие «Выпускной YYYY»)
3. Интерфейс «альбома» с покадровой навигацией

---

### 6.3. Раздел «Благодарности»

**Требование:** Возможность оставить запись в честь преподавателя или однокурсника.

**Текущее состояние:** ❌ Отсутствует.

**Рекомендация:** Создать коллекцию `Tributes` (id, author_person_id, target_person_id, text, date, status). Реализовать страницу `/tributes` с фильтрацией по целевым персонам.

---

## 7. Метаданные

### 7.1. Обязательные поля

**Требование:** Год, Автор (если известен), Ключевые персоны (имена), Событие/Повод.

**Текущее состояние:**

| Поле | Тип | Наличие |
|------|-----|---------|
| Год | `date_taken` | ✅ Есть |
| Автор | `uploaded_by` | ✅ Есть (uuid пользователя) |
| Ключевые персоны | `people` (текст) | ⚠️ Текстовое, без связей |
| Событие/Повод | — | ❌ Отсутствует |

**Рекомендация:**
1. Добавить поле `event` (relation → `Events`)
2. Заменить `people` на связь many-to-many `Archive ↔ Persons`
3. Добавить поле `author_name` (text) для указания автора фото (если неизвестен пользователь системы)

---

### 7.2. Справочник персон

**Требование:** Вести отдельную базу данных по всем упоминаемым персонам, даже если их фото ещё нет в архиве.

**Текущее состояние:** ❌ Отсутствует.

**Рекомендация:** Коллекция `Persons` (см. Ось 3) — ключевая. Она позволит:
- Связывать новые материалы с уже известными людьми
- Искать по фамилии/имени
- Автоматически агрегировать все упоминания
- Создавать «карточки персон»

## 9. Рекомендуемый порядок доработок

### Этап 1: Ядро данных (недели 1-4)
1. Коллекция `Persons` (карточки людей)
2. Коллекция `Events` (карточки событий)
3. Коллекция `Faculties` (факультеты/кафедры)
4. Связи many-to-many: `Archive ↔ Persons`, `Archive ↔ Events`
5. Автоматическое заполнение `decade` из `date_taken`

### Этап 2: Навигация и фильтры (недели 5-8)
1. Фильтр по году (конкретному)
2. Фильтр по факультету
3. Фильтр по типу контента
4. Коллекция `Tags` (тематические теги)
5. Тематические подборки

### Этап 3: Интерактив для выпускников (недели 9-12)
1. Саморегистрация + роль `Alumni`
2. Личный кабинет выпускника
3. Альбомы выпусков
4. Раздел «Благодарности»
5. Комментарии/обсуждения

### Этап 4: Продвинутые функции (недели 13+)
1. Роль `CourseModerator` (модерация по курсу)
2. Система подтверждений (moderation queue)
3. Полнотекстовый поиск по документам (OCR)
4. Поиск по лицу (Face Recognition)

## 10. Технические ограничения Directus

| Ограничение | Обходное решение |
|-------------|-----------------|
| Нет саморегистрации по умолчанию | `REGISTRATION_ENABLED: true` в env |
| Нет системы комментариев | Отдельная коллекция `Comments` с привязкой к записям |
| Нет «избранного» | Отдельная коллекция `Favorites` (user_id ↔ archive_id) |
| Нет виртуальных альбомов | Коллекция `Albums` + связь many-to-many |
| Нет системы «благодарностей» | Коллекция `Tributes` |
| Нет OCR/Face Recognition | Отдельные Docker-сервисы + API |

## 11. Выводы

**Текущая реализация (v1.0.0)** покрывает базовые функции:
- Публичная галерея с фильтрами
- Загрузка файлов
- Минимальная система ролей

**Требования** описывают значительно более сложный продукт — «живой мемориальный портал» с:
- Многомерной классификацией (5 осей)
- 4 уровнями доступа
- Справочником персон и событий
- Интерактивом для выпускников

**Общий GAP:** ~70% требований не реализованы. Наиболее критичные:
1. Справочник персон (без него невозможно связать материалы с людьми)
2. Карточки событий (без них нет событийной оси)
3. Факультеты/кафедры (без них нет структурной оси)

**Сроки:** При текущем темпе разработки (1-2 недели на этап) полная реализация займёт ~3-4 месяца.
