## 1. Введение

### 1.1. Контекст

Фонд «Технологическому институту — 200 лет» эксплуатирует систему электронного архива исторических материалов СПбГТИ по адресу `archive.ti200.ru`. Текущая версия (v1.0.0) обеспечивает базовый функционал: загрузку файлов, публичную галерею, минимум фильтров.

### 1.2. Проблема

Текущий архив работает как **хранилище** (загрузил → посмотрел), но не как **сервис** для поиска и навигации. Основные проблемы:

- Нет структурированных метаданных (факультеты, персоны, события)
- Нет связей между записями (одно фото не привязано к людям/событиям)
- Фильтры ограничены (только категория и десятилетие)
- Интерфейс не adapté для не-технических пользователей (выпускники, сотрудники)

### 1.3. Ожидаемый результат

Архив должен стать **живым мемориальным порталом**, где:

- Выпускник находит «свой» выпуск и видит всех однокурсников
- Сотрудник быстро находит все материалы по факультету за определённый год
- Каждая запись связана с людьми, событиями и темами
- Навигация возможна по 5 осям: хронология, структура, персоны, события, темы

## 2. Цели и задачи

### 2.1. Цели

| № | Цель | Ключевой показатель |
|---|------|---------------------|
| Ц1 | Превратить архив из хранилища в сервис | 80% пользователей находят нужный материал за < 3 кликов |
| Ц2 | Обеспечить персональный поиск | Выпускник находит фото своего выпуска и однокурсников |
| Ц3 | Стандартизировать каталогизацию | 100% новых записей имеют метаданные (год, факультет, персоны) |

### 2.2. Задачи

| № | Задача | Связь с целью |
|---|--------|---------------|
| З1 | Создать справочник персон (студенты, преподаватели, выпускники) | Ц2, Ц3 |
| З2 | Создать справочник факультетов/кафедр | Ц3 |
| З3 | Создать справочник событий (выпускные, мероприятия) | Ц1, Ц3 |
| З4 | Настроить связи many-to-many (записи ↔ персоны, события, теги) | Ц1, Ц2, Ц3 |
| З5 | Разработать интерфейс загрузки с метаданными | Ц3 |
| З6 | Разработать интерфейс просмотра с фильтрами | Ц1 |
| З7 | Разработать админ-панель для управления справочниками | Ц3 |

## 4. Функциональные требования

### 4.1. Управление справочниками

#### 4.1.1. Справочник персон

**Назначение:** Хранение информации о людях, связанных с институтом.

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| Имя | text | да | ФИО |
| Год рождения | integer | нет | Год рождения |
| Год смерти | integer | нет | Год смерти (если применимо) |
| Роль | select | да | Студент / Преподаватель / Сотрудник / Выпускник |
| Факультет | relation | нет | Связь со справочником факультетов |
| Год выпуска | integer | нет | Для выпускников |
| Кафедра | text | нет | Если известна |
| Номер группы | text | нет | Учебная группа |
| Биография | text | нет | Краткая биография |
| Фото | file | нет | Фотография персоны |

**Операции:**
- Создание / Редактирование / Удаление карточки
- Поиск по имени (частичное совпадение)
- Фильтр по роли, факультету, году выпуска
- Просмотр всех связанных записей архива

#### 4.1.2. Справочник факультетов

**Назначение:** Отражение исторической структуры института.

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| Название | text | да | Полное название факультета |
| Сокращение | text | нет | Аббревиатура (напр. «ФЭТ») |
| Описание | text | нет | Описание факультета |
| Период деятельности | text | нет | Годы существования (напр. «1930-наст. время») |
| Статус | select | да | Действующий / Архивный |

**Начальные данные:** Исторические факультеты СПбГТИ (9 шт.)

#### 4.1.3. Справочник событий

**Назначение:** Фиксация значимых событий и мероприятий.

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| Название | text | да | Наименование события |
| Дата | date | нет | Дата проведения |
| Дата окончания | date | нет | Для много дневных мероприятий |
| Описание | text | нет | Подробности |
| Тип | select | да | Выпускное / Конференция / Праздник / Другое |
| Обложка | file | нет | Главное изображение |
| Место | text | нет | Место проведения |
| Статус | select | да | Черновик / Опубликовано |

#### 4.1.4. Справочник тегов

**Назначение:** Тематическая классификация записей.

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| Название | text | да | Уникальное название тега |
| Группа | text | нет | Тематическая группа |
| Цвет | color | нет | Для визуального отображения |

**Начальные данные:** Базовые тематические теги (8 шт.)

---

### 4.2. Связи между записями

#### 4.2.1. Запись ↔ Персоны

**Тип:** Many-to-many
**Назначение:** Позволяет привязать одну запись к нескольким людям (и наоборот).

| Дополнительное поле | Тип | Описание |
|---------------------|-----|----------|
| Тип связи | select | Автор / На фото / Упомянут |

**Примеры использования:**
- Фото выпускного 1985 года связано с 20 выпускниками (тип: «На фото»)
- Фотография Иванова И.И. связана с 50 записями (тип: «Автор»)

#### 4.2.2. Запись ↔ События

**Тип:** Many-to-many
**Назначение:** Привязка записей к событиям (мероприятиям, выпускным, конференциям).

**Пример:** Все фото с Дня открытых дверей 2023 года связаны с событием «День открытых дверей 2023».

#### 4.2.3. Запись ↔ Теги

**Тип:** Many-to-many
**Назначение:** Тематическая классификация.

**Пример:** Запись имеет теги «Научные лаборатории», «1980-е», «Физический факультет».

### 4.3. Интерфейс загрузки

**URL:** `/upload`
**Для кого:** Редакторы

#### Требования:

- Drag & drop загрузка (множественная)
- Автоматическое определение типа файла (фото/видео/документ)
- Обязательные поля: Название, Файл
- Рекомендуемые поля: Год, Факультет
- Дополнительные поля: Персоны, Событие, Теги
- Прогресс загрузки
- Предпросмотр перед загрузкой
- Статус новой записи: `draft`

---

### 4.4. Интерфейс просмотра

**URL:** `/browse`
**Для кого:** Все пользователи (Наблюдатели, Редакторы, Администраторы)

#### Фильтры:

| Фильтр | Тип | Источник |
|--------|-----|----------|
| Год | диапазон / выпадающий список | Поле `date_taken` |
| Факультет | выпадающий список | Справочник `faculties` |
| Тип контента | чекбоксы | Фото / Видео / Документ |
| Персона | поиск | Справочник `persons` |
| Событие | выпадающий список | Справочник `events` |
| Теги | чекбоксы | Справочник `tags` |

#### Отображение:

- Masonry-сетка (как текущая галерея)
- Лайтбокс для просмотра
- Информация о записи: название, дата, факультет, персоны, событие
- Навигация между записями

---

### 4.5. Админ-панель

**URL:** `/admin`
**Для кого:** Администраторы

#### Функции:

- Управление справочниками (персоны, факультеты, события, теги)
- Просмотр статистики (всего записей, по факультетам, по персонам)
- Публикация записей (draft → published)
- Массовые операции (добавление тегов, привязка к событиям)
- Экспорт данных (CSV, JSON)

## 7. Интеграции

### 7.1. Текущий стек

| Компонент | Технология | Роль |
|-----------|-----------|------|

| БД | PostgreSQL 16 | Хранение записей, справочников, связей |
| Фронтенд | Vanilla HTML/CSS/JS | Интерфейс (кастомный) |

| Веб-сервер | nginx | Прокси, раздача статики |

### 7.2. API-эндпоинты (расширенные)

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/items/Archive` | Список записей (с фильтрами) |
| GET | `/items/Archive/:id` | Детали записи |
| POST | `/items/Archive` | Создание записи |
| PATCH | `/items/Archive/:id` | Редактирование записи |
| DELETE | `/items/Archive/:id` | Удаление записи |
| GET | `/items/persons` | Список персон |
| GET | `/items/persons/:id` | Детали персоны + связанные записи |
| GET | `/items/faculties` | Список факультетов |
| GET | `/items/events` | Список событий |
| GET | `/items/events/:id` | Детали события + связанные записи |
| GET | `/items/tags` | Список тегов |
| GET | `/items/archive_persons` | Связи записей с персонами |
| GET | `/items/archive_events` | Связи записей с событиями |
| GET | `/items/archive_tags` | Связи записей с тегами |

### 7.3. Параметры фильтрации

```javascript
// Фильтр по году
GET /items/Archive?filter[date_taken][_gte]=1980&filter[date_taken][_lte]=1989

// Фильтр по факультету
GET /items/Archive?filter[faculty_id][_eq]=<uuid>

// Фильтр по персоне (через связь)
GET /items/Archive?filter[persons][_in]=<person_uuid>

// Фильтр по событию (через связь)
GET /items/Archive?filter[events][_in]=<event_uuid>

// Фильтр по тегу (через связь)
GET /items/Archive?filter[tags][_in]=<tag_uuid>

// Комбинированный фильтр
GET /items/Archive?filter[faculty_id][_eq]=<uuid>&filter[date_taken][_gte]=1980&filter[tags][_in]=<tag_uuid>
```
