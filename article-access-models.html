Модели доступа: кому что можно показывать

Почему единый доступ = плохо, и как построить систему, которая защищает и даёт находить

1. Почему единый доступ — плохо

Есть два крайних варианта, и оба — плохо:

  • Всё открыто: утечка персональных данных, штрафы, скандалы. Студенты видят чужие дипломы, приказы о увольнении, личные фото.
  • Всё закрыто: архив мёртв. Никто не пользуется. Выпускники не могут найти себя. Пресса не может написать о юбилее. Спонсоры не видят лицо института.

Правильный путь: Гибридная модель. Часть данных — открыта для мира. Часть — доступна сотрудникам и выпускникам. Часть — только для архивистов. Это баланс между безопасностью и полезностью.

2. Модель A: Полностью публичный

Открытый доступ

Open Access

Кто видит: любой посетитель сайта, поисковики, пресса, спонсоры.

Что видит: маркетинговые фото, общие планы, пресс-релизы, фото зданий, тематические подборки без персон.

Примеры: MIT Distinctive Collections, Stanford Digital Repository, Yale Open Access.

Плюсы

  • Максимальная видимость: поисковики индексируют, пресса находит
  • Престиж: институт показывает свою историю миру
  • Привлечение: абитуриенты и спонсоры видят лицо института

Минусы

  • Нельзя публиковать персональные данные без согласия
  • Риск: «почти публичные» данные могут быть интерпретированы как нарушение

3. Модель B: Аутентифицированный

Аутентификация

Authenticated Access

Кто видит: сотрудники, студенты, выпускники — все, кто может подтвердить связь с институтом.

Что видит: все фото с их участием, внутренние документы, справочники людей, события.

Как работает: вход по вузовскому email, SSO, или ручная верификация.

Плюсы

  • Сообщество: выпускники находят себя и друг друга
  • Безопасность: только верифицированные пользователи
  • Ценность: архив становится полезным для живого сообщества

Минусы

  • Сложнее технически: нужна система аутентификации
  • Барьер: не каждый выпускник готов «регистрироваться»

4. Модель C: Закрытый

Закрытый доступ

Restricted Access

Кто видит: только архивисты, администраторы, юристы.

Что видит: личные дела, приказы, дипломы с оценками, полные метаданные.

Когда: запрос на исследование, юридическая проверка, внутренний аудит.

Когда нужно

  • Запрос от правоохранительных органов
  • Юридические споры (трудовые, наследственные)
  • Исследовательские запросы с обоснованием

5. Модель D: Гибридная (рекомендуемая)

Рекомендация: Использовать все три уровня одновременно. Каждый уровень — своя «стена» с правилами доступа.

Уровень Кто видит Что видит Как получить доступ
Public Мир Здания, буклеты, маркетинг, общие фото событий Никаких барьеров
Authenticated Сотрудники + выпускники Фото с участием, внутренние события, справочники Email вуза / верификация
Restricted Архивисты Личные дела, приказы, дипломы Заявка + одобрение

6. Верификация пользователей

Ключевой вопрос: как доказать, что ты выпускник или сотрудник?

Вариант 1: Вузовский email

Самый простой. Сотрудники имеют @ti200.ru. Выпускники — нет. Не подходит для alumni.

Вариант 2: Ручная верификация

Пользователь отправляет заявку: ФИО, год выпуска/работы, факультет. Админ проверяет по базе и одобряет. Трудоёмко, но точно.

Вариант 3: Справка от отдела кадров

Пользователь загружает скан справки. Админ подтверждает. Быстро, но требует ручной работы.

Вариант 4: Связь через LinkedIn/VK

Авторизация через соцсети. Быстро для пользователя, но сложнее технически и зависит от третьих сторон.

Для СПбГТИ: Начните с варианта 2 (ручная верификация). Позже автоматизируйте через email-домен @ti200.ru для сотрудников.

7. Разделение архива: 20/70/10

Рекомендуемое распределение данных по уровням:

Уровень Доля Содержимое Цель
Public 20% Здания, маркетинг, пресса, общие фото Привлечение, престиж, SEO
Authenticated 70% Фото людей, события, справочники Сообщество, ценность для alumni
Restricted 10% Личные дела, приказы, дипломы Безопасность, юридика

8. План внедрения

Этап 1: Публичный слой (неделя 1-2)

  • Выставить фото зданий, корпусов, общие планы
  • Добавить пресс-релизы, буклеты, презентации
  • Настроить SEO: мета-теги, OG, sitemap

Этап 2: Аутентификация (неделя 3-4)

  • Настроить вход по email для сотрудников
  • Добавить форму заявки для выпускников
  • Открыть внутренний слой для верифицированных

Этап 3: Закрытый слой (неделя 5)

  • Настроить роли: guest / user / editor / admin
  • Переместить личные данные в restricted
  • Добавить аудит-лог действий

Главный принцип

Начните с малого: 20% публичных данных. Это даёт результат за 2 недели. Остальные 80% — постепенно, по мере получения согласий и верификации сообщества.
